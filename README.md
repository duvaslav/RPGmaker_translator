# RPG Maker Translator

Десктопное GUI-приложение для автоматического перевода игр на RPG Maker MV/MZ.
Парсит JSON, защищает управляющие коды, переводит через DeepL/Google/Yandex
или через локальную языковую модель, сохраняет прогресс и собирает обратно
работоспособную копию игры.

## Что умеет

- **Поддержка всех ключевых файлов RPG Maker MV/MZ**:
  Map###.json, CommonEvents.json, Troops.json, Actors/Items/Weapons/Armors/Skills/Enemies/States/Classes/MapInfos.json, System.json
- **Защита управляющих кодов**: `\C[1]`, `\N[2]`, `\V[5]`, плагин-теги `\FFF[...]`, `\N<имя>`, `\{`, `\}` и др.
- **Защита системных обозначений**: `switches`, `variables`, имена Common Events/Troops, plugin-теги `<...>`, `%1/%2` и строки, похожие на JS/идентификаторы, не отправляются в переводчик.
- **Контекстная склейка** многострочных диалогов в один запрос к переводчику
- **Вёрстка сообщений** (главное для качества, см. раздел ниже):
  - авторские переносы склеиваются ПЕРЕД отправкой, поэтому переводчик видит
    целые предложения, а не обрывки строк
  - после перевода текст заново переносится по реальной ширине окна, измеренной
    настоящим шрифтом игры
  - если строк стало больше, чем показывает окно, сообщение раскладывается на
    несколько окон **по границам предложений**
- **Глоссарий имён**: персонажи из `Actors.json` и теги `\N<…>` не отправляются
  в переводчик, поэтому «Airy» остаётся «Айри», а не становится «Воздушным»
- **Безопасные границы реплик**: части контекстного диалога заключаются в
  нумерованные HTML-контейнеры, поэтому переносы переводчика не смешивают
  разных говорящих и не перемещают управляющие коды между окнами
- **Цепочки перевода с pivot**: JP→EN→RU, JP→RU, EN→RU и любые другие
- **Свой провайдер на каждой стадии**: например, JP→EN через Google, EN→RU через DeepL
- **Анализ объёма перед запуском** — точные цифры символов и % от лимита DeepL Free
- **Распределение по языкам** в проекте
- **Языковой фильтр** — переводить только строки на нужном языке (для частично переведённых игр)
- **Тестовый прогон 1–2 файлов** перед полным переводом — проверка качества
- **Постоянный кэш переводов** (`_translation_cache.json` в выходной папке):
  - Автосохранение после каждого батча
  - Возобновление прерванной работы (по ошибке, по лимиту, по stop)
  - Дедупликация одинаковых строк (имя персонажа переводится один раз)
- **Пауза / Продолжить** прямо во время перевода
- Тёмная тема, асинхронный воркер, не зависает

## Установка

```bash
pip install -r requirements.txt
python run.py
```

## Использование

### Шаг 1: API-ключи

- **DeepL**: deepl.com/pro-api → «API Keys». Free = 500к символов/мес. Free-ключи кончаются на `:fx`, Pro — нет. Endpoint определяется автоматически.
- **Yandex**: console.cloud.yandex.ru → IAM → API Keys. Ключу нужна роль `ai.translate.user`. Folder ID — в правом верхнем углу консоли (формат `b1g...`). В приложении вводится отдельно от ключа. Если в пакет попадает больше ~10 000 символов, Yandex может вернуть ошибку — приложение само разобьёт такой пакет на куски по 5 000 символов.
- **Google**: без ключа, через `deep-translator`. На больших объёмах ловит rate limit — уменьши batch_size.
- **Локальная модель**: ключ не нужен вовсе. Настройки — на вкладке «Локальная модель», см. раздел ниже.

### Шаг 2: Перевод

1. Папка Data игры (обычно `Game/www/data` или `Game/data`)
2. Выходная папка — туда копия с переводом. Исходник не трогается.
3. Маршрут: исходный → (промежуточный) → целевой. Pivot опционален.
4. Провайдер для каждой стадии.
5. **«Анализ объёма»** — точные цифры символов, расход DeepL Free, языковое распределение.
6. (Опц.) **«Тестовый прогон»** — 1–2 файла для проверки. Результат в папку `..._TEST`.
7. После анализа в «Языковом фильтре» появятся чекбоксы языков. Сними галки тех, что переводить не нужно.
8. **«Запустить перевод»**.

Опция **«Автоперенос по реальной ширине окна»** включена по умолчанию. Если
выбрана папка `www/data` (а выходная папка находится рядом в том же `www`),
программа установит `js/plugins/Translator_AutoWrap.js` и зарегистрирует его
последним после списка штатных плагинов. Перед первым изменением создаётся
`index.html.pre_translator_autowrap.bak`. Повторная установка безопасна и не
дублирует подключение.

### Управление во время работы

- **«Пауза»** — останавливает на текущем батче, потом продолжает с того же места.
- **«Остановить»** — корректно завершает, частичный перевод и кэш сохранены.
- При ошибке API (лимит, сеть) то же: успевшие переводы остаются в кэше.

### Возобновление

Перевод прервался? Просто запусти ещё раз с той же выходной папкой. Воркер найдёт кэш, подхватит уже переведённое и продолжит с того места. Никаких дублей в API.

### Очистка кэша

Кнопка **«Очистить кэш»** удаляет `_translation_cache.json`. Следующий запуск переведёт всё заново.

## Вёрстка сообщений — почему это главное

RPG Maker хранит текст уже разбитым на строки под ширину окна, и разбит он
часто посреди фразы:

```
~Link Event 1 (Panty Flash Discovery)~ Trigger
Condition: Break Time \N[1] accidentally catches a
glimpse of Natsubo's panties... What action does
Airy, who saw him looking, take...?
```

Если отдать это переводчику как есть, каждая строка становится отдельным
сегментом. Результат предсказуемо плохой: «Trigger» без «Condition» — это
«спусковой крючок», «catches a» и «glimpse of» переводятся как два обрывка,
а имя «Airy» превращается в «Воздушный». Именно поэтому раньше тот же Yandex,
куда человек вставлял абзац целиком, давал заметно лучший результат.

Конвейер устроен так (`core/text_fit.py`):

1. **Расклейка.** Перенос считается вёрсточным, если строка почти дотянулась до
   края окна и не заканчивается знаком конца предложения. Такие переносы
   склеиваются. Авторский перенос после точки и короткая строка с именем
   говорящего сохраняются.
2. **Перевод.** Провайдер получает связный текст.
3. **Перенос.** Результат переносится по фактической ширине окна. Ширина
   считается настоящим шрифтом игры из `www/fonts`, если установлен Pillow;
   иначе — по таблице для M+ 1m, штатного шрифта MV/MZ. Учитываются портрет
   (−168 px), иконки `\I[n]` и подстановка `\N[n]` реальным именем героя.
4. **Разбивка на окна.** Предложения набираются в окно по одному, и текст окна
   переносится целиком — строки остаются плотно заполненными, а граница окна
   всегда совпадает с концом фразы. Каждое новое окно получает копию команды
   `101`, поэтому портрет и имя говорящего сохраняются.

Опция включена по умолчанию («Пересобирать вёрстку сообщений»).

### Глоссарий

`_glossary.json` в выходной папке — список терминов, которые не отправляются в
переводчик:

```json
{"version": 1, "terms": {"Airy": "Айри", "Natsubo": "Нацубо", "Break Time": ""}}
```

Значение — форма в переводе; пустая строка = оставить как в оригинале. Файл
создаётся автоматически из `Actors.json` и тегов `\N<…>`, дальше правится
руками. Имена подставляются в именительном падеже и не склоняются — это
осознанный компромисс: «подошёл к Айри» читается лучше, чем «подошёл к
Воздушному».

## Защита управляющих кодов (важно!)

Управляющие коды RPG Maker (`\C[1]`, `\N[2]`, `\V[5]`, `\N<имя>`, плагин-теги), системные плейсхолдеры (`%1`, `%2`) и plugin-теги (`<WordWrap>`, `<name:...>`) **не должны переводиться**, иначе сломается логика игры или на экране появятся лишние символы.

Приложение защищает их так: перед отправкой в переводчик каждый код заменяется на HTML-тег-плейсхолдер `<t0/>`, `<t1/>` и т.д. Переводчик переводит текст вокруг, но теги оставляет нетронутыми — для этого включён режим:
- DeepL: `tag_handling=html`
- Yandex: `format=HTML`
- Google: html-теги не трогает по умолчанию

После перевода теги восстанавливаются обратно в исходные коды. Короткие
плагин-коды без параметров (например, `\c` для сброса цвета и `\w`) тоже
защищаются: сервис не сможет превратить их в кириллические `\с`/`\ш`.

При контекстной группировке каждая исходная команда `401` дополнительно
оборачивается в `<rpgline data-i="N">...</rpgline>`. Провайдер видит весь
диалог, но после ответа каждая реплика возвращается строго в своё окно — число
добавленных сервисом переносов строк на это больше не влияет.

**Почему именно HTML-теги, а не символы вроде `⟦P0⟧`:** машинные переводчики искажают экзотические Unicode-символы — превращают `⟦` в `⟧`, в кавычки `"`, латинскую `P` в кириллическую `Р`. HTML-теги они обязаны сохранять. Это решает проблему порчи кодов на корню.

**Дополнительная защита:** после перевода приложение проверяет границы,
количество и уникальность всех плейсхолдеров. Если сервис потерял контейнер или
код, повреждённая строка не записывается: в игре остаётся безопасный текст
источника, а в лог попадает точное имя файла. Восстановление терпимо к мелким
изменениям тега (регистр, лишние пробелы, потерянный слеш).

Также приложение не переводит системные имена `switches`/`variables`, имена Common Events и Troops, а строки, похожие на скрипты, пути ресурсов или plugin-идентификаторы, помечает как технические. Имена из базы данных (`Actors`, `Items`, `Skills`, `Enemies` и т.д.) тоже не переводятся, если такое имя встречается в script/plugin/comment командах или JS-файлах игры: это защищает проверки вида `$dataItems[id].name === "..."`. Они остаются в JSON без изменений, но обычные названия и описания, которые не используются скриптами как идентификаторы, продолжают переводиться.

## Предпросмотр

Кнопка **«Предпросмотр»** берёт случайные отрывки переведённых диалогов и показывает их рядом с оригиналом. Управляющие коды подсвечены, проблемы отмечены красным. Кнопка «Другие отрывки» подбирает новый случайный набор. Это позволяет визуально проверить качество перевода и целостность кодов, не запуская игру.

## Безопасность данных

- Выходная папка **удаляется целиком** перед копированием проекта, поэтому
  перед запуском проверяется, что она не содержит исходную папку, не находится
  внутри неё и не хранит посторонние файлы. Раньше выбор `www` при источнике
  `www/data` уничтожал игру вместе с исходником.
- Если папка существует и не похожа на прошлую выходную, приложение спрашивает
  подтверждение.
- JSON-файлы игры пишутся атомарно (временный файл + `os.replace`), поэтому
  обрыв на середине записи не оставит битую карту.
- Переводы с повреждёнными управляющими кодами **не попадают в кэш** — иначе
  битая строка осталась бы в нём навсегда и никогда не переводилась заново.
- Ключ кэша включает провайдера: смена Google на DeepL заставит перевести
  заново, а не подсунет старый результат. У локальной модели в ключ входит ещё
  и отпечаток модели, инструкции и параметров генерации — при их смене прежний
  перевод был бы ответом на другой вопрос.

## Локальная модель

Вместо облачного сервиса переводчик умеет обращаться к языковой модели,
запущенной на этой же машине через OpenAI-совместимый API (LM Studio и
подобные). Интернет и ключи не нужны, текст игры никуда не уходит.

**Сервером управляет пользователь.** Приложение не запускает и не
останавливает LM Studio, не загружает и не выгружает модель — только
проверяет связь и внятно сообщает, если её нет.

### Чем это отличается от облачного перевода

DeepL, Google и Yandex — переводчики: дали список строк, получили список той
же длины. Модель — исполнитель инструкции. Она может переставить элементы,
склеить их, потерять управляющий код или оборвать ответ на середине. В
измерениях на Qwen3.5-4B Q4_K_M сохранность управляющих кодов составила
80.7 % без строгой схемы ответа и 93.3 % со схемой — то есть **инструкция
модели в принципе не может быть механизмом безопасности**.

Поэтому обмен построен на контракте:

1. Каждая строка уходит со своим идентификатором, своим контекстом и
   метаданными. Общей строки контекста на весь пакет нет: пакет собирает
   реплики из разных сцен, и подсказка от чужой сцены увела бы перевод.
2. Ответ обязан соответствовать строгой JSON Schema и разбирается **по
   идентификатору**, а не по позиции.
3. Каждый перевод проверяется детерминированным валидатором: состав, кратность
   и порядок плейсхолдеров; положение кода относительно числа (`700<t0/>` не
   должно стать `<t0/>700` — иначе в игре будет «¥700» вместо «700¥»);
   сохранность чисел; отсутствие Markdown, преамбул и чужих управляющих кодов;
   факт того, что перевод вообще сделан.
4. Не прошедшая строка переспрашивается **одна** и **другой инструкцией**.
   Повторять тот же запрос бесполезно: при температуре 0 модель трижды из трёх
   повторяет один и тот же дефект.
5. Если и ремонт не помог, строка остаётся исходной и попадает в отчёт.
   **Ни в игру, ни в кэш испорченный перевод не пишется.**

### Настройка

Вкладка «Локальная модель»:

| Поле | Значение по умолчанию | Почему |
|---|---|---|
| Адрес сервера | `http://127.0.0.1:1234/v1` | Нелокальный адрес отклоняется: в запросах едет текст игры |
| Идентификатор модели | `qwen3.5-4b-rpg-ru-safe` | Должен совпадать с `/v1/models` символ в символ |
| Температура / top_p / top_k | 0 / 0.8 / 20 | Воспроизводимый результат |
| Размер пакета | 5 | Безопасно при 16 ГиБ ОЗУ; 10 быстрее и проверен на 32 ГиБ; 20 быстрее ещё на 2 %, но на нём терялся код |
| Контекст | 1 реплика до и после | Шире — не лучше: на широком контексте модель чаще теряла коды |
| Строгая JSON-схема | включена | Без неё корректный JSON приходил в 13 случаях из 15 |

Кнопка **«Проверить соединение»** отвечает на три вопроса по отдельности,
потому что лечатся они по-разному: поднят ли сервер, загружена ли **нужная**
модель, отвечает ли она по контракту.

Если установлен `psutil`, перед каждым пакетом проверяется свободная
оперативная память: при остатке меньше 1.5 ГиБ перевод останавливается, не
начиная новый пакет. Модель на 4 млрд параметров занимает при работе около
12.7 ГиБ, и уход в подкачку вешает не только перевод, но и рабочий стол.
Переведённое к этому моменту уже лежит в кэше, так что запуск продолжится с
того же места.

### Что делать с непереведёнными строками

Строки, которые не прошли проверку и не починились с одной попытки, остаются
исходным текстом, а их список пишется в `_translation_failures.json` рядом с
переводом: идентификатор, стадия, исходный текст и причина. Повторный запуск
переведёт их заново — в кэш они не попали.

### Чего ждать

Модель работает медленнее облака: около 36 минут на 1 000 строк при пакете 10
и около 40 минут при пакете 5, плюс 10–25 % на проверки и повторы. Качество
на трудных местах ниже: идиомы и многозначные слова (`Save her!` в смысле
«спаси её») она берёт буквально. Это **черновой переводчик под вычитку**, а не
замена платному сервису.

## Замечания

- Поле `note` у элементов БД не трогается (там обычно плагин-теги).
- Парсер не модифицирует исходную папку — всегда работает на копии.
- При включённом автопереносе меняются только `www/index.html` и добавляемый
  `www/js/plugins/Translator_AutoWrap.js`; исходный `index.html` сохраняется в
  резервную копию. Сами исходные JSON по-прежнему не изменяются.
- Поддерживается только MV/MZ (JSON). VX Ace и старше (.rvdata2) не поддерживаются.
- `pip install Pillow` не обязателен, но даёт перенос с точностью до пикселя на
  играх с нестандартным шрифтом.
- Проверка без сети и без GUI: `python self_test.py`.
- Команды `355` (скрипты плагинов) не переводятся.
- Команда `101` (header диалога) НЕ разрывает цепочку 401-команд — это специально для игр, где имена говорящих хранятся в отдельных 401-строках с плагин-тегами (как в твоей игре).

### Ремонт результата старой версии

Если игра уже была собрана старым алгоритмом и показывает `<t2 />`, `<t0` или
смешанные реплики, восстановление запускается из корня переводчика:

```powershell
.\.venv\Scripts\python.exe -m core.dialogue_repair --game "D:\путь\к\игре" --install
```

Модуль требует сохранённые `www\data_old\data` и
`www\data\_translation_cache.json`. Он создаёт сборку отдельно, повторно
использует только однозначно проверяемый кэш, переводит сомнительные строки
заново и меняет `www\data` лишь после поиска остаточных `<tN/>` и кириллических
backslash-кодов. Старая папка остаётся рядом как
`www\data_before_dialogue_repair_<дата>`.

## Зашифрованные игры (CryptoJS AES)

Некоторые игры RMMZ имеют пропатченный движок, который шифрует все `data/*.json` через CryptoJS AES (в начале файла видна строка `U2FsdGVkX1...`).

Приложение работает с такими играми **прозрачно**:

1. При выборе папки Data приложение **само определяет**, зашифровано ли всё (по префиксу `Salted__`).
2. Если да — пытается **автоматически найти ключ** в `js/rmmz_managers.js` рядом с папкой Data, даже если код плагина обфусцирован: эвристика собирает строковые литералы и проверяет каждый против реального зашифрованного файла, пока не получится валидный JSON.
3. Найденный ключ подставляется в поле «Ключ шифрования» под папкой Data. Можно вписать вручную, если автодетект не сработал.
4. Кнопка **«Найти автоматически»** запускает поиск повторно, и предлагает выбрать `rmmz_managers.js` вручную, если рядом с папкой Data его нет.
5. При переводе все файлы расшифровываются при чтении и **зашифровываются обратно** при записи — игра без модификаций сможет их прочитать.

Если автодетект не находит ключ, открой `js/rmmz_managers.js` в блокноте и найди строку вида:
```
CryptoJS.AES.decrypt(x, 'секретный_ключ')
```
Скопируй то, что внутри кавычек, и вставь в поле «Ключ шифрования».

## Подсказки по экономии лимитов

- **Гибрид JP→RU**: первая стадия Google (бесплатно), вторая DeepL (качество).
- **Прямой JP→RU через DeepL** обычно лучше JP→EN→RU — экономит лимит вдвое.
- **Дубли строк** (имена, команды меню) кэшируются автоматически. В большой игре ~20-30% экономии.
- **Языковой фильтр** для частично переведённых игр.
